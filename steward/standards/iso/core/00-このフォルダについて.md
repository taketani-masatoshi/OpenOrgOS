# core — ISO 共通コアモジュール

**ゾーン:** フレームワーク定義 · **規格 ID を持たない**（`standards.yaml` には現れない）

複数の ISO が同じ仕事を要求する部分を、**条項番号ではなく仕事の型**で1件にまとめた統制。各規格パックは `core_bindings` で自分の条項番号を宣言する。

---

## なぜ条項番号をキーにしないか

| 仕事 | Annex SL | ISO 13485 |
| --- | --- | --- |
| 内部監査 | 9.2 | 8.2.4 |
| マネジメントレビュー | 9.3 | 5.6 |
| 力量 | 7.2 | 6.2 |
| 文書化した情報 | 7.5 | 4.2.4 |
| リスク | 6.1 | 7.1 |

同じ仕事でも規格と改定で番号が動く。テナントの成熟度は仕事側に残す。

## 統制一覧

| ID | work | 証拠の満たし方 |
| --- | --- | --- |
| `CTL-CORE-scope` | scope | all |
| `CTL-CORE-policy` | policy | all |
| `CTL-CORE-risk-approach` | risk_approach | all |
| `CTL-CORE-objectives-monitoring` | objectives_monitoring | all |
| `CTL-CORE-competence` | competence | any |
| `CTL-CORE-doc-control` | documented_information | any |
| `CTL-CORE-operation` | operation | all |
| `CTL-CORE-internal-audit` | internal_audit | any |
| `CTL-CORE-management-review` | management_review | any |
| `CTL-CORE-corrective-action` | corrective_action | all |

`evidence_mode`:

- **any** — 共有成果物が1つあればよい（監査計画 · MR 議事録 · 文書管理規程）
- **all** — 有効な規格ごとに固有の成果物が要る（リスク登録 · 方針 · スコープ文書）。27001 を足したら 27001 のリスク登録が別に要る、という意味

---

## 領域メソッドは畳まない

リスクは全規格に出るが、方法は規格ごとに違う。次はコアではなく各パックに残す。

- ISO 27001 適用宣言書（SoA）· ISO 13485 の ISO 14971 リスクファイル
- ISO 45001 危険源 · ISO 22301 BIA · ISO 22000 HACCP
- ISO 14001 環境側面 · ISO 37001 贈収賄リスク評価
