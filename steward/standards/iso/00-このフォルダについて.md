# steward/standards/iso — ISO 標準テンプレート（フレームワーク）

**ゾーン:** フレームワーク定義 · **対象:** 全テナント共通の ISO 規格説明・方針ドラフト・記録様式。

テナント固有のギャップ評価・監査記録・成熟度は **`tenants/{id}/docs/compliance/iso/`** に置く。本フォルダは **コピー元・参照正本** とし、MAL 等の会社名・物件名は含めない。

---

## 共通コアモジュール

HLS（Annex SL）が全規格に要求する仕事は [core/](core/00-このフォルダについて.md) に1件ずつ集約されている。
各規格パックは `core_bindings` で自分の条項番号をコアに結ぶだけでよい。

規格を1つ有効化すると、その規格の条項付きで共通統制が自動的に載る。パックに書くのは
**その規格にしかない仕事**（危険源 · BIA · HACCP · EnPI · SLA · 贈収賄リスク · 環境側面 · 設計管理）だけ。

## Coming Soon

[catalog.yaml](catalog.yaml) に `status: coming_soon` で登録済み。パックは未作成で、テナントでは有効化できない。

| Tier | 内容 | 例 |
|------|------|-----|
| 1 | OOO の性格上、次に来る | ISO 42001（AI MS）· 37301（CMS）· 27701（PIMS 2025 単独認証） |
| 2 | 既存モジュールに接続 | 55001 · 20121 · 41001 · 30401 · 56001 · 28000 · 46001 |
| 3 | ガイダンス — パックにせずコアの `guidance_refs` へ | 31000 · 19011 · 26000 · 22316 |
| 4 | 管理策集・セクタ拡張 — 単独 MS ではない | 27002/27017/27018 · 14064/14068 · 10002 |

```bash
orgos iso roadmap --tier 1
orgos iso scaffold ISO-42001 --dry-run   # core_profile からパック雛形を生成
```

Tier 3・4 は `scaffold` を拒否する。単独のマネジメントシステムではないため。

## テナントでの使い方

1. 対象規格の `00-このフォルダについて.md` と `policy-template.md` を読む
2. 必要な様式を `tenants/{id}/docs/compliance/iso/ISO-XXXX/` にコピーしてカスタマイズ
3. ギャップ評価・監査記録・steward-assessment はテナント側のみ更新
4. Compliance Agent は本フォルダを **Read**、テナント `docs/compliance/iso/**` を **R/W**

## 統制マップ（control-map.yaml）

機械可読の正本索引は [catalog.yaml](catalog.yaml)。各パックに **条項 ↔ REG ↔ Agent ↔ 証拠パス** の `control-map.yaml` を置く（ISO 公式本文ではない）。

```bash
orgos iso catalog [--status available|coming_soon]
orgos iso roadmap [--tier 1|2|3|4]
orgos iso maps verify        # coming_soon は skip
orgos iso scaffold <id>
orgos iso audit run
orgos iso audit report
```
