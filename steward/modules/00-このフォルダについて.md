# steward/modules — 業務モジュールカタログ

Steward OS **フレームワーク**の業務モジュール定義。テナントが `modules.yaml` で **ON/OFF** し、物件・データパスをバインドする。

## コア Agent vs 業務モジュール

| 種別 | パス | 常時 |
|------|------|------|
| **コア Agent** | [steward/core/agents/](../core/agents/00-このフォルダについて.md) | Executive · Secretary · Finance · Contract · Compliance · Operations |
| **業務モジュール** | **本フォルダ** | テナントごとに `enabled: true/false` |

### 宣言系（JP · Compliance 連携）

## 業務モジュール（横断）

法人非依存の業務モジュール。`steward/modules/{id}/` に配置。

**法域固有モジュール**（宣言系等）は各 Jurisdiction Pack 内 `modules/` に分離:

| モジュール id | 法域 | パス |
|---------------|------|------|
| `jp_carbon_neutral_2050` | JP | `steward/jurisdiction-packs/JP/modules/` |
| `jp_women_empowerment` | JP | 同上 |
| `jp_privacy_policy` | JP | 同上 |
| `jp_subsidy_application` | JP | 同上 · 補助金申請執筆支援 |
| `jp_trademark_application` | JP | 同上 · 商標出願 · 登録願ひな形 |

契約: [../jurisdiction-packs/pack_contract.md](../jurisdiction-packs/pack_contract.md)

## トークン節約

- **無効モジュール**（`enabled: false`）の `agent.md` · `skills/` · `seed/` は Agent が **読まない**
- 有効範囲は `npm run steward -- modules sync-context` で `tenants/{id}/rules/active_context.md` に生成
- `.cursor/rules/tenant-active-context.mdc` が Cursor に有効パスのみ指示

## カタログ構成

```
steward/modules/{id}/
├── agent.md          Agent 定義（汎用）
├── skills/           モジュール Skill
└── seed/             雛形データ（YAML · CSV · MD）
```

テナントは `modules.yaml` で **パスをバインド** するのみ。seed は `steward/modules/{id}/seed/` からコピーしてテナント `data/` · `docs/` に展開する。

## テナントでの有効化

```yaml
# tenants/{id}/modules.yaml
modules:
  - id: rental
    enabled: true
    agent: rental
    property_ids: [PROP-001]
    docs_root: docs/properties/PROP-001-minato/operations/
    summary_dir: agent-summaries/rental/
```

```bash
# seed からコピー（例: venture_capital）
cp steward/modules/venture_capital/seed/*.example data/venture-capital/
npm run steward -- modules list
npm run validate
```

## 新モジュール追加手順

正式な契約・手順は [module_contract.md](module_contract.md) を参照（manifest スキーマ · tier 要件 · classification proxy）。要約:

1. `module.manifest.yaml`（`id` 必須）と `agent.md` を作成
2. 必要なら `{id}/skills/` · `{id}/seed/`（`*.example`）
3. `schemas/modules.ts` の `moduleAgentId` に id 追加
4. `readiness.yaml` に tier 登録 → `modules check {id}` → `npm run check`
5. テナント `modules.yaml` にエントリ追加（パスバインドのみ）

## Readiness tier（3 段階）

正本: [readiness.yaml](readiness.yaml) · ロジック: `src/lib/module-readiness.ts`

| tier | 意味 | モジュール |
|------|------|-----------|
| **production_ready** | activation + billing/invoice CLI 連携 | rental · hospitality · restaurant · professional_services · saas_subscription（5） |
| **activation_ready** | テナント有効化 seed 一式 | … · **jp_carbon_neutral_2050 · jp_women_empowerment · jp_privacy_policy**（宣言系 JP） |
| **skeleton** | カタログ骨格（manifest · agent · seed/ のみ） | （現状なし） |

`npm run steward -- modules list` / `modules check --all` の Tier 列を参照。
