# 社内規程の起草スタイル（申し送り）

**対象:** 社内規程の新規作成・改定・草案を行う Agent / Operator（Compliance を含む）  
**正本:** 本ファイル · **適用例:** `tenants/*/docs/company/regulations/` 施行文  
**参考正本（体裁）:** `tenants/mal/docs/company/regulations/ringi-kessai-kisoku.md`

---

## 1. 原則

会社規程の本文は、**権利義務・手続・責任**を人が読んで理解できる文章とする。  
リポジトリのパス、ファイル名、CSV 等の**媒体・実装の詳細**は本文に埋め込まず、**別紙**に整理する。

| 層 | 書くこと | 書かないこと（本文） |
|----|----------|----------------------|
| **条文（第○条）** | 何をするか · 誰が · いつまでに · どの区分か | `docs/...` · `data/...` · `*.csv` · CLI · 英語ロール ID |
| **別紙** | 台帳の記載項目 · 保管場所の対応 · 様式の項目 | 無理に CLI や実装コードを義務付けない |

別紙では、フォルダ構成やファイル名を示してよい（運用接続のため）。媒体形式を義務づける必要はない。

---

## 2. 文書の並び（必須）

1. ヘッダ（会社名・規程ID・版・制定日／改定日）
2. `## 第1条` … `## 第N条（改定）`
3. `---`
4. `## 別紙1（…）`（必要なら別紙2…）
5. `---`
6. `## 関連`

別紙は **改定条の直後・関連の直前** に置く。外出しディレクトリに散らさない（同一ファイル内）。

条文からは「別紙1」「所定の記録場所（別紙1）」のように参照する。

---

## 3. 文体

- 「本規程は〜を定める。」「〜してはならない。」「〜を要する。」
- 定義が必要なら第○条（定義）に項番で置く
- 表は決裁区分・役割・保管期間など**規範に直結するもの**を条文に残してよい
- ADR・Skill・エージェント名を本文に書かない（関連又は別紙の実装参照に限る）

---

## 4. アンチパターン（禁止）

```markdown
# BAD — 条文に実装パス・形式
1. 契約は [`docs/contracts/`](...) および [`契約管理表.csv`](...) に登録する。
```

```markdown
# GOOD — 条文は手続、詳細は別紙
1. 契約を締結したときは、契約文書を所定の保管場所に置き、契約台帳（別紙1）に必要な事項を記載する。

## 別紙1（契約台帳）
| 項番 | 記載項目 | …
（必要なら保管場所のパスを別紙表に記載）
```

---

## 5. 作業手順（Agent）

1. 対象 REG のカタログ行・既存施行文を読む  
   Path: `steward/jurisdiction-packs/JP/regulations/catalog.yaml`
2. 条文ドラフトを先に書き、実装詳細は別紙へ退避する
3. 改定のときは版番号・改定案日付をヘッダに明記する（未施行なら「草案」）
4. `tenants/{id}/regulations.yaml` の enabled / notes を必要なら更新する
5. 取締役会承認後に施行日を確定し、対応表（regulation-bindings）がある場合は凍結手順を別途行う
6. Compliance Agent 定義を改定したら `orgos operator export --agent compliance` を実行する

Cursor 利用時（任意）: `@steward/jurisdiction-packs/JP/regulations/00-起草スタイル.md`
