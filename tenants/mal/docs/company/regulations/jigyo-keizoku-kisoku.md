# 事業継続・危機管理規程

**株式会社MAL**  
**規程ID:** REG-013  
**版:** v1.0（制定）  
**制定日:** 2026年6月6日（取締役会決議）  
**関連規格:** ISO 22301:2019

---

## 第1条（目的）

本規程は、災害・障害・事故等の **重大事象** 発生時に、生命・安全を最優先し、宿泊サービス及び経営機能を可能な限り継続又は早期復旧する手順を定める。

## 第2条（適用範囲）

1. 亀沢旅館の予約・チェックイン/アウト・ゲスト安全
2. 本社の経営判断・契約・決算・Steward OS
3. 翻訳・SES 案件の納期維持（可能な範囲）

## 第3条（基本方針）

重大な障害発生時も、**生命・安全を最優先** し、事前に整備した連絡網・代替手段によりサービスと経営判断を継続する。

## 第4条（優先シナリオと目標）

| シナリオ | 初期対応 | 目標復旧 |
|---------|---------|---------|
| PMS/OTA 停止 | 電話・メールでゲスト対応 | **RTO 4時間** |
| 亀沢停電・設備故障 | ゲスト安全確保、避難誘導 | **24時間** 安全確保 |
| 火災・地震 | 119/110、ゲスト避難、近隣連絡 | 人命最優先 |
| 本社 PC・ネット障害 | 副端末・モバイル回線 | **RTO 48時間**（経営判断） |
| データ消失 | Git・OTA エクスポートから復旧 | **RPO 24時間** |

詳細手順は [`docs/compliance/iso/ISO-22301/`](../../compliance/iso/ISO-22301/) に置く。

## 第6条（代替手段）

1. **通信:** モバイルルータ、スマートフォンのテザリング
2. **鍵・入室:** スマートロック障害時の物理鍵の保管場所を2名で共有
3. **予約:** OTA アプリ・電話予約の手動記録（スプレッドシート等）
4. **経営データ:** Git リモート、クラウドバックアップ

## 第7条（訓練・見直し）

1. **年1回**、桌面訓練（シナリオ想定・連絡確認）を実施し記録する。
2. 実災害・重大インシデント後は **30日以内** に手順を見直す。
3. [REG-012](shukuhaku-unyo-kisoku.md)・[REG-009](joho-security-kanri-kisoku.md) と整合させる。

## 第8条（緊急支出）

[REG-004 稟議・決裁規程](ringi-kessai-kisoku.md) 第6条（緊急時）に従い、初動対応後 **7日以内** に報告・承認を得る。

## 第9条（改定）

本規程の改定は、取締役会の決議による。
