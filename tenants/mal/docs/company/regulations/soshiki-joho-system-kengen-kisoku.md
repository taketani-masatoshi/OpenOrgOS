# 組織情報システム権限管理規程

**株式会社MAL**  
**規程ID:** REG-030  
**版:** v1.0  
**制定日:** 2026年7月15日（取締役会決議）  
**施行日:** 2026年7月15日  
**ステータス:** 施行

---

## 第1条（目的）

本規程は、会社が業務の遂行に用いる組織情報システム（以下「本システム」という。）における利用者の権限、承認手続、監査及び情報の開示範囲を定め、適正かつ安全な運用を確保することを目的とする。

## 第2条（適用範囲）

1. 本規程は、本システムを通じて会社の業務データに触れるすべての操作に適用する。
2. 契約、支出及び投資等の金額に基づく決裁区分は、[稟議・決裁規程](ringi-kessai-kisoku.md)（以下「決裁規程」という。）の定めによる。本規程は、当該区分を本システム上で実行するときの権限及び手続を定める。

## 第3条（定義）

本規程において、次の各号に掲げる用語の意義は、当該各号に定めるところによる。

1. **操作者** 本システムに登録され、操作を行う役員又は従業員その他これに準ずる者をいう。
2. **業務処理機能** 本システム上で所定の業務を処理する機能（人が指示し、又は補助させるものを含む。）をいう。
3. **重要操作** 振込の指示、組織間の正式な送信に係る承認、対外通信の最終送信、権限の拡大その他会社に重大な影響を及ぼし得る操作をいう。
4. **指示監査記録** 操作者又は業務処理機能に対する指示及び重要操作の経過を、改変を想定しない形で保存する記録をいう。
5. **権限台帳** 操作者の役割、所属、許可する業務範囲及び権限を記録した台帳をいう。
6. **対応表** 本規程その他社内規程と権限台帳等の実装記録との対応関係を、取締役会が承認した時点の内容として固定する表をいう。

## 第4条（権限の基本方針）

1. 会社は、本システムにおける重要操作の権限を、原則として代表取締役（操作者として登録された者を含む。以下本条において同じ。）に集中させる。
2. 承認を担当する操作者は、あらかじめ権限台帳に記載された範囲、又は第7条の期限付き付与による場合を除き、重要操作を行ってはならない。
3. 前項と異なる権限の分散方式に変更するときは、本規程の改定及び対応表の再承認を要する。

## 第5条（操作者の区分）

操作者は、次の区分により権限台帳に登録する。

| 区分 | 権限の概要 | 行ってはならないこと |
|------|------------|----------------------|
| 代表取締役（業務執行） | 業務執行に必要な権限（重要操作を含む。） | — |
| 承認担当 | 権限台帳又は期限付き付与に記載された範囲の承認 | 付与のない重要操作 |
| 一般操作 | 下書き、照会その他委任された処理 | 付与のない重要操作 |
| 監査閲覧 | 指示監査記録及び必要な範囲の閲覧 | 差止、送金、承認、対外送信その他の実行 |
| 閲覧のみ | 閲覧 | 変更及び承認 |
| 外部連携サービス | あらかじめ許可された処理に限る | 許可外の処理 |

2. 同一の者が、代表取締役（業務執行）の区分と監査閲覧の区分とを兼ねてはならない。

## 第6条（部門ごとの利用範囲）

1. 操作者には、組織上の所属部門を紐付けることができる。
2. 部門に属する操作者は、権限台帳に定められた業務処理機能及びデータの範囲でのみ操作しなければならない。
3. 前項の範囲を超える操作が必要なときは、第7条の手続による。

## 第7条（期限付きの権限付与）

1. 操作者は、上位の承認者に対し、業務処理機能、データの範囲又は追加権限の期限付き付与を申請することができる。
2. 申請をした者と承認する者は、同一であってはならない。
3. 付与には有効期限を定めなければならない。期限の経過又は取消し後は、直ちに効力を失う。
4. 付与の経過は、権限台帳又はこれに準ずる記録に残す。

## 第8条（重要操作の承認）

重要操作は、次の表に定める承認を経た後でなければ実行してはならない。

| 操作 | 承認者 |
|------|--------|
| 組織間の正式な送信 | 代表取締役（業務執行）又は承認権限を付与された者 |
| 社内稟議に基づく実行 | 決裁規程の区分に従う承認者 |
| 振込の指示 | 振込権限を付与された者。口座番号等の機微な値を対話画面に表示し、又は転記してはならない。 |
| 対外電子メールの最終送信 | 下書きについて承認を得た後に限る。 |
| 対応表の固定（施行セットの確定） | 取締役会の決議（又はこれと同等の承認）の後 |

2. 決裁規程に定める金額区分と、本システム上の承認の取扱いは、整合させなければならない。

## 第9条（指示監査記録）

1. 会社は、重要操作及びこれに準ずる重要な指示について、指示監査記録に追記する。
2. 監査閲覧の区分の操作者は、指示監査記録を閲覧することができる。実行のための権限は有しない。
3. 指示監査記録について、削除のみを目的とする機能は設けない。

## 第10条（業務処理機能及び情報の開示）

1. 経営概況の補助を担う業務処理機能は、ダッシュボード、各機能の要約及び経営メモの範囲を超えて、業務データの正本を直接読み取ってはならない。
2. 部門の業務処理機能は、担当として割り当てられた業務フォルダの範囲でのみ処理する。
3. 情報の機微さに応じた取扱いは、会社が定める分類の基準による。次の趣旨を遵守する。

| 区分 | 自動処理 | 対話画面・文書への出力 |
|------|----------|------------------------|
| 公開又はこれに準ずる情報 | 可 | 業務上必要な範囲で可 |
| 業務上の機微情報 | 担当者の明示的な参照又は担当機能に限る | 会社が追跡する一般文書及び対話画面への転記を禁止する |
| より高い機微情報 | 禁止 | 前項の情報の要約への混入を禁止する |

4. 口座及び個人の住所等は、識別子による参照にとどめ、その値を対話画面に表示してはならない。

## 第11条（規程と権限台帳の対応）

1. 権限台帳、権限の基本方針に関する記録その他本規程の実装に係る記録は、対応表に登録する。
2. 取締役会が対応表を固定した後は、固定した内容と現行の記録が一致しない状態で重要操作を実行してはならない。
3. 規程全文の意味の照合を、都度の人工知能の判定のみに委ねて実行の可否を決めてはならない。

## 第12条（決裁規程との関係）

1. 決裁規程第2条及び第3条に定める代表取締役双方の合意の原則は、議事録その他書面による手続において引き続き効力を有する。
2. 本システム上の日常の操作については、第4条の方針に基づき、代表取締役（業務執行）として登録された操作者が、決裁規程区分 A に相当する範囲の承認を単独で行うことができる。
3. 決裁規程区分 B 以上に相当する金額又は重要度の操作は、本システム上においても共同の承認又は取締役会の記録を要する。システム上の手続がこれに足りないときは、人の手続により補完する。

## 第13条（他の規程との関係）

1. 情報資産へのアクセスの一般原則は、[情報セキュリティ管理規程](joho-security-kanri-kisoku.md)の定めによる。本規程は、本システム固有の権限及び手続を補完する。
2. 書類及びデータの保管場所は、[文書管理規程](bunsho-kanri-kisoku.md)の定めによる。
3. 年次の内部監査及び相互監査は、[内部監査規程](naibu-kansa-kisoku.md)の定めによる。本規程第5条の監査閲覧は、システムの指示監査記録の閲覧であり、内部監査規程に定める監査に代わるものではない。

## 第14条（改定）

本規程の制定及び改定は、取締役会の決議による。施行の際は、対応表を固定し、会社の記録として残す。
