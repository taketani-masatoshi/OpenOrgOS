# 消込トランザクションの障害復旧

消込は仕訳とイベントの更新前に両ファイルの復旧用コピーを永続化します。途中の状態が残れば新しい仕訳・消込・期間ロック操作と対象の読取を停止します。確認できない台帳を空の台帳として扱わないでください。

復旧は対象テナントの最新の operator registry にある active な ceo / approver に限定します。finance:reconcile 権限と鍵の一致、有効期限、規程バインディングを確認します。開発用の認証省略は適用しません。AIA の実行コンテキストからの復旧は拒否します。

```sh
# ORGOS_OPERATOR_KEY は承認者自身の安全な環境から設定する。引数やログに鍵を書かない。
npm run finance:recover-reconciliation -- --tenant=TENANT_ID --confirm-recovery --operator-id=OPERATOR_ID --reason='障害番号と復旧理由'
```

- `restored`: 永続化された更新前の内容に復旧した。
- `committed`: 既にコミットされた両ファイルのハッシュを確認し、残ったマーカーを整理した。
- `none`: 未完了トランザクションがない。

`started` を記録してから復旧を実行し、両ファイルの書込み・fsync・ハッシュ確認の後に `completed` を記録します。completed は台帳の復旧完了を意味し、マーカー整理の成否とは分けます。整理失敗なら failed と未完了マーカーを残し、同じ復旧を再実行できます。completed はトランザクション単位で重複させません。

新しい監査記録は `data/finance/.reconciliation-recovery-audit/` に一イベント一ファイルで保存し、イベントID・試行ID・連番・前イベントのハッシュを持ちます。一時ファイルを書き、fsync 後に rename して公開します。既存の `reconciliation-recovery-audit.jsonl` は変更せず、最初の記録の前ハッシュとして固定します。監査に台帳本文や鍵は含めません。ハッシュ連鎖は破損・途中の変更の検出用で、外部署名・WORM保管による改ざん耐性や末尾削除の検出を保証するものではありません。

プロセスロックはホスト・PID・一意な所有者ファイルを持ちます。同一ホストで所有者の終了を確認できたロックだけを、認証済み復旧で回収します。生きているプロセス、別ホスト、所有者不明の旧形式ロックは解除しません。旧形式ロックが残る環境は、書込みプロセスを停止して保全コピーを確保した上で管理者が所有状況を調査してください。共有ネットワークFSや複数ホストのフェイルオーバーは検証対象外です。

復旧記録は整理時に `.reconciliation-finished-*` へ原子的に移し、復旧操作では証拠として残します。正常な処理のコピーは切離し後に削除します。異常終了時の `.reconciliation-preparing-*` / `.finance-owner-*` は台帳更新前の一時領域です。これらも台帳のコピーを含み得るため非公開データとして保管し、実運用の保持期間に従って管理してください。

検証: 合成テナントで認証拒否、途中書込み失敗、再実行、監査記録破損、コミット後の整理失敗、SIGKILL 後の復旧、生存ロックの保護を確認。実テナント復旧、電源断、別ホスト、ブラウザE2Eの検証を意味しません。
