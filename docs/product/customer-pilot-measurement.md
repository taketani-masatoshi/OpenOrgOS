# 顧客業務の効果測定

最初の測定対象は「銀行 CSV 取込から消込・承認・月次締め・仕訳 CSV 出力まで」です。基準値と導入後を同じ業務範囲・会社規模・取引種別で比較します。テスト結果から実顧客の削減効果を推定しません。

## 記録

[空テンプレート](pilot-observations.template.json) を社内の承認済み保管先へコピーし、1 業務試行につき 1 観測を記録します。失敗・途中離脱も含めます。再試行には別 ID を振ります。

```json
{
  "case_id": "anonymous-case-001",
  "data_kind": "synthetic",
  "cohort": "pilot",
  "observed_at": "2026-09-22T00:00:00.000Z",
  "completed": false,
  "transactions": 100,
  "work_minutes": null,
  "assistance_minutes": null,
  "approval_wait_minutes": null,
  "corrections": null,
  "incidents": null
}
```

これは形式例で実績ではありません。`observations` 配列に観測を入れます。`production` は実際の顧客業務、`synthetic` は練習・デモです。`baseline` は導入前、`pilot` は導入後。未計測は `null`、測定してゼロだった場合だけ `0` とします。氏名・銀行明細・金額・顧客名は不要です。

## 指標

| 指標 | 定義 | 欠測・分母 |
|---|---|---|
| 完走率 | 完了試行 / 全試行 | 未観測は null。失敗も分母に含む |
| 作業分 / 100 件 | 完了試行の実作業分合計 / 対応する取引件数合計 × 100 | 実作業分のある完了試行だけ。待ち時間と支援者時間を除く |
| 支援分 / 試行 | 導入支援・操作介助者の作業分合計 / 計測試行数 | 失敗時の介助も含む |
| 承認待ち分 / 試行 | 承認依頼から判断までの経過分合計 / 計測試行数 | 複数依頼は試行内で合算 |
| 訂正件数 / 100 件 | 操作・転記誤りに起因する訂正件数合計 / 対応する取引件数合計 × 100 | 通常の会計調整は除く |
| 障害件数 / 試行 | 業務中断・誤計上・権限逸脱等の件数合計 / 計測試行数 | ゼロと未観測を分離 |
| 作業時間削減率 | (導入前の作業分/100件 − 導入後の作業分/100件) / 導入前 | 導入前が未観測・ゼロなら null |

各値に計測件数と欠測件数を併記します。合成と実績は必ず別集計です。削減率は記述的比較であり、取引構成や習熟度の差を調整した因果効果ではありません。成功例だけの作業時間改善は、完走率や支援負担と併せて判断します。

## 集計

```bash
npm run product:pilot-report -- /absolute/path/to/observations.json
```

指定したファイルだけを読み、匿名の集計 JSON を標準出力へ出します。業務テナントを探索・更新しません。空テンプレートの実績値はすべて未計測になります。形式不備・同一種別/群/ケースの二重記録・負数は拒否します。

継続条件は、まず比較可能な導入前後の観測を揃え、完走率・作業時間・支援負担・訂正を同時に評価することです。データ損失・権限逸脱・帳簿不整合が起きた場合は当該経路を停止し、原因を解消してから再検証します。商用拡大の数値目標・判断は実績が揃った時点で責任者が決定します。
