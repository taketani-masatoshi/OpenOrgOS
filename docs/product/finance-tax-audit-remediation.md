# 会計・税務監査15件の5分割対応（2026-09-22）

対象はCore正本。元報告の15件に対し、下記順序で実装した。確定できる入力の計算修正と、根拠不足・未対応入力の拒否を区別する。未対応計算をすべて実装したという意味ではない。実テナントのデータ補完、移行、承認、申告、commit/pushは実行していない。

## 第1群：消費税 C1〜C4

- C1：売上は貸方−借方、購入は借方−貸方で集計。取消・翌月返品は負数として保持し、負の仕入税額を0に丸めない。
- C2：GL/科目表の例外を伝播。台帳不存在、破損、復旧待ちは計算停止。有効な空台帳のみ0円。独立した手動計算は売上4区分・購入2区分の6金額をすべて明示する。
- C3：資産科目も課税購入対象。AR/現金など決済行には `out_of_scope` を用いる。
- C4：`taxable_only` + `qualified` + `tax_amount_yen` の明細税額を符号付きで集計。`non_taxable_only` は控除しない。共通用途、登録不明、経過措置は期間全体の適用条件を検証できないため停止。月次予算から生成した費用は証憑情報を持たず、控除対象と推定しない。

制限：共通用途の按分・経過措置の年額上限等を自動計算するエンジンは未実装。手動の一括移行率をGLに掛ける旧CLIオプションだけでは計算を続行できない。期間全体の確認を経た完全な手動計算か、対応済み明細が必要。取引日・証憑・税額の実データを自動補完しない。

## 第2群：給与・税率 P1/P2/T1/I1

この章のP1/P2は元報告の給与観測IDで、優先度ではない。

- P2：2026年の月額甲欄・電算機計算を実装。社会保険控除後の金額、給与所得控除の1円切上げ、基礎控除の所得段階、扶養人数、税額の10円四捨五入を適用。28万円・社会保険41,300円・扶養0人は5,720円。
- P1：tenantの `payroll-rates-YYYY.yaml` がなければ停止。exampleへのフォールバックを廃止。適用暦年・`effective_from`/`effective_to`（YYYY-MM）・`insurer_id` を要求。健康保険と厚生年金の確定標準報酬を別入力にし、給与額から同じ等級を推定しない。
- T1：2025-04-01以後に開始する事業年度の所得10億円超に17%分岐を追加。元報告の11億円のケースは254,704,000円。
- I1：基準所得税の100円切捨てを廃止し、復興特別所得税・源泉・予定納税の後の最終納付額で端数処理。課税所得149,000円の例は7,600円。

給与の入力：`computePayrollMonth` の `healthStandardRemunerationYen` / `pensionStandardRemunerationYen`。月次締めでは `payroll.yaml` の `employee_payroll.health_standard_remuneration_yen` / `pension_standard_remuneration_yen`。税務APIには同名snake_case入力を追加。料率と標準報酬の実際の決定・確認は利用者側で必要。

制限：給与源泉は2026年の月額甲欄のみ。他年は拒否。乙欄・賞与・年末調整・保険者ごとの全条件をこの修正で保証していない。法人税の特殊法人・短期事業年度・地方税・防衛特別法人税を網羅した変更でもない。

## 第3群：締め・期首 A1/A2/A3/O1

- A1：P/L振替は科目残高の正負と正常残高方向を保持。借方売上・貸方費用もゼロにする。
- A2：翌期開始残高・損益振替のハッシュを先に永続化。元の期首残高を状態ファイルに保持し、切替前/後の`committing`を再開する。再開時に月次証跡・銀行・元期首を使った試算表・振替・提案を再照合し、改変があれば停止。転記重複を防止。
- A3：銀行CSV取込と月次/年次締めは共通のfinance書込みロックで直列化。締め済み月の取込を拒否。月次証跡は銀行明細内容と月末の再生済み消込状態を含める。年次締めで仕訳・銀行・試算表の3ハッシュを再検証。
- O1：期首残高の通常保存は締め履歴が一度でもあれば拒否。年次繰越は専用の検証済み経路から実行。

導入制約：旧方式の月次ハッシュや必要情報のない年次状態は自動変換しない。人間の権限で元証跡を確認し、必要な再締め・復旧を行う。ローカルFSの障害状態・再試行を検証した範囲であり、電源断・ネットワークFSの保証ではない。

## 第4群：請求書・償却 B1/D1

- B1：請求書仕訳へ `counterpartyId` を渡す。生成サービスはbillingの `counterparty_id` またはCLI `--counterparty-id` を使う。不明なら転記・成果物生成前に停止。ARの既存必須ガードは保持。
- D1：定額償却を未償却簿価−1円までに制限。固定資産スナップショット後の過去月の転記額を差し引き、継続転記と同月再実行で過剰償却を防ぐ。除却月の翌月から計上停止。

制限：この定額法は既存の帳簿用月割りを保全したもので、法定償却率表の完全実装ではない。スナップショットより前の月の再計算は拒否。定率法は年度期首・保証額・改定取得価額を正しく確定できる実装がないため、推定計算を廃止して拒否する。資産台帳や既存仕訳は書き換えない。

## 第5群：電子帳簿 E1・統合検証

`append_only_ok` / `search_index_ok` の無条件trueを廃止。`verification_status: unverified` と `verification_gaps` を返し、readinessで合格扱いにしない。検索機能と既存の監査項目検査は保持。外部の独立した改変検知基準・検索要件の運用証拠を取得する仕組みは別途必要。今回、電帳法適合を認証したわけではない。
