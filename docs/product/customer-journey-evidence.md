# 顧客業務完走証跡

OrgOS Ledger の最初の顧客業務を、実装の存在だけでなく一つの完走経路として確認するための正本です。

## 対象経路

会社登録 → 初回手動仕訳 → 銀行 CSV のテンプレート取得 → dry-run → 本取込 → 一部・残額消込 → 仕訳提案 → 承認 → 月次期間ロック → readonly 利用者への仕訳 CSV 出力を、合成テナントで検証します。既存請求の売掛金と対応仕訳は合成の開始データとして投入します。

自動検証の正本は [`tests/customer-journey-http.test.ts`](../../tests/customer-journey-http.test.ts) です。専用ランナーは業務パス・鍵の環境変数を除外し、製品コードの import 前から一時 workspace を指定します。従来の実テナント fixture 復元処理は使いません。一時データは実行後に削除します。

拒否条件も検証します：重複 CSV の追加なし、未消込・一部消込での締め拒否、readonly の承認・締め拒否、提案だけでは未計上、二重承認拒否、ロック済み月への追記拒否。消込の取消・無効化・壊れたイベントの読取も確認します。

これは HTTP 統合検証です。セッションは合成で、Passkey 操作、CSRF、settlement step-up、外部 AI、課金、ブラウザ操作はこのテストの対象外です。「人間が実画面で承認した」「AI が正しく仕訳を推論した」という証拠にはしません。

## 証跡の区分

| 区分 | 意味 | 現在の証拠 |
|---|---|---|
| 実装済み | API/UI/CLI のコードが存在する | Core の製品コード・ルート実装 |
| 自動検証済み | 対象版・環境のテストが成功し、結果を保存した | 各実行の `evidence.json` と `vitest.json`。コマンドの存在だけでは合格にしない |
| 本番実証済み | 隔離された実顧客環境で、人間が完走を確認した | **未記録** |

自動テストが緑でも、本番実証済みには昇格させません。本番実証には、実施日、環境、匿名化したケース ID、担当役割、結果、未解決事項を社内の承認済み保管先に記録します。Git に顧客名・実テナント識別子・秘密・顧客本文を記録しません。

## 実行

```bash
cd Core
npm run test:customer-journey
```

実行ごとに `test-results/customer-journey/run-*/`（Git 対象外）へ結果を保存します。時刻、HEAD、追跡差分ハッシュ、検証コードハッシュ、終了コード、件数、合否、制約を記録します。空・スキップ・中断した実行を合格にしません。CI は失敗時も結果を artifact に保存します。

Core Release は `release-check` 成功後に作成し、npm 公開も同じ検証に依存します。独立した demo-docker 公開経路は既存の Docker smoke が条件であり、顧客 HTTP 統合検証とは別です。

効果の測定は [customer-pilot-measurement.md](customer-pilot-measurement.md) を参照してください。自動テスト時間は顧客の作業時間に算入しません。
